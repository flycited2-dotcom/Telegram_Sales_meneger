# Sales Bot Training Plan

Цель: сделать бота не генератором случайных ответов, а менеджером по продажам с понятной воронкой, обучаемыми фразами и проверяемыми сценариями.

## Главный принцип

Не строим "огромный промпт на все случаи". Строим три слоя:

1. Intent router: понимает, что клиент делает сейчас.
2. Slot extractor: вытаскивает товар, бренд, бюджет, размер, мощность, цвет, количество, контакт.
3. Sales state machine: ведет клиента по этапам: подбор -> уточнение -> список -> выбор -> заказ -> уведомление.

LLM можно оставить для живого языка, но решение "что искать", "что показывать" и "можно ли оформить заказ" должен принимать код.

## Воронка

| Блок | Что делает клиент | Что должен делать бот |
| --- | --- | --- |
| greeting | Привет, здравствуйте, добрый день | Ответить живо одной из 3-5 фраз и спросить, что подобрать |
| discovery | Клиент примерно говорит товар | Понять категорию, не показывать аксессуары вместо основного товара |
| qualification | Клиент дает параметры | Собрать слоты: бренд, бюджет, мощность, площадь, цвет, No Frost и т.д. |
| listing | Бот нашел варианты | Показать 3-5 лучших вариантов, не 12-50 позиций |
| more | Клиент пишет "еще", "давай еще" | Показать следующую страницу из той же выдачи |
| selection | Клиент пишет номер или модель | Выбрать строго из последнего показанного списка |
| checkout | Клиент согласен купить | Собрать количество, имя, телефон; затем создать заказ |
| complaint | Клиент недоволен или пишет "что ты шлешь" | Извиниться коротко, не искать каталог, вернуться к последнему нормальному товару |
| no_match | Точного товара нет | Честно сказать, что точного нет, и дать безопасные альтернативы только той же категории |

## Почему текущая версия ломается

1. Последний показанный список не хранится отдельно. Из-за этого "11 позицию" может выбрать товар из старого или смешанного списка.
2. Основной товар и аксессуары смешаны. Поэтому на "холодильник" вылезает поглотитель запаха для холодильника.
3. Бренды не нормализованы. "BEKO" работает, "Беко" и "бе4о" почти нет.
4. Checkout не является состоянием. После выбора товара телефон и имя снова попадают в поиск по каталогу.
5. Слова вроде "заказываю" могут ошибочно восприниматься как "заказ".

## Обучаемая таблица

Файл `data/sales_training_examples.csv` должен пополняться реальными фразами. Формат:

| Поле | Зачем нужно |
| --- | --- |
| block | Блок воронки: greeting, discovery, qualification, listing, more, selection, checkout, complaint, no_match |
| intent | Конкретное намерение: find_product, ask_price, select_position, provide_contact |
| user_phrase | Как реально написал клиент |
| slots | Что бот должен извлечь |
| bot_action | Что должен сделать код |
| good_reply | Пример нормального ответа |
| bad_reply_guard | Что запрещено делать |

## Параметры по категориям

| Категория | Основные слоты | Важные правила |
| --- | --- | --- |
| Кондиционер | мощность 7/9/12/18/24, площадь м2, инвертор/on-off, бренд, бюджет, завод/компрессор, фреон, Wi-Fi | 12 BTU примерно 35 м2, 7-9 BTU примерно 20 м2; не показывать расходники, если клиент просит сам кондиционер |
| Холодильник | бренд, No Frost, цвет, высота, объем, морозилка сверху/снизу, бюджет | Не показывать поглотители запаха, фильтры, аксессуары |
| Телевизор | диагональ, Smart TV, бренд, бюджет, разрешение | На "32 диагональ" искать телевизоры 32", не аксессуары |
| Микроволновка | бюджет, объем литры, гриль, цвет, бренд | Если до бюджета ничего нет, предложить ближайшие дороже |
| Генератор | инверторный/обычный, мощность кВт, бензин/газ, автозапуск, бюджет | Не показывать AVR/блоки автопуска, если клиент просит генератор |
| Чайник | бюджет, объем, материал, бренд | На "до 800" показывать 3-5 вариантов, не весь каталог |
| Стиральная машина | кг, инвертор, пар, глубина, бренд, бюджет | "8 кг" это параметр, не номер позиции |
| Водонагреватель | литры, сухой ТЭН, вертикальный/горизонтальный, бренд, бюджет | "сухой тэн" обязательный фильтр |

## Вариативность приветствия

Нужны группы ответов, а не один текст:

| Вход | Возможные ответы |
| --- | --- |
| привет | "Здравствуйте. Что подобрать по технике?", "Добрый день. Напишите товар или бюджет, подберу варианты.", "Приветствую. Что ищем: кондиционер, холодильник, бойлер или другое?" |
| добрый день | "Здравствуйте. Что нужно подобрать?", "Добрый день. Напишите категорию и бюджет, сориентирую по наличию." |
| доброго дня | "Здравствуйте. Подскажите, какой товар нужен?", "Добрый день. Могу сразу показать варианты из наличия." |

## Режим рольплея

Мы можем обучать так:

1. Я играю клиента и пишу 10-15 реальных фраз.
2. Ты отвечаешь как менеджер.
3. Я превращаю хорошие ответы в `sales_training_examples.csv`.
4. Потом мы добавляем тесты, чтобы бот отвечал так же или лучше.

## Сайт splithub.ru

Сайт можно использовать как источник знаний по кондиционерам и FAQ, но не стоит дергать его в каждом диалоге. Правильная схема:

1. Периодически парсить сайт.
2. Сохранять локальный справочник: бренды, линейки, преимущества, FAQ, соответствие BTU и площади.
3. На запрос клиента искать в каталоге, а пояснения брать из локального справочника.

Так бот будет быстрым и не сломается, если сайт временно недоступен.

## Ближайший технический план

1. Добавить `last_shown_product_ids` отдельно от `interested_product_ids`.
2. Добавить `selected_product_id`, `selected_quantity`, `client_contact`, `checkout_stage`.
3. Сделать жесткий выбор позиции только из `last_shown_product_ids`.
4. После выбора товара не искать каталог по телефону или имени, а продолжать checkout.
5. Ограничить выдачу 3-5 товарами и добавить "показать еще".
6. Разделить основные товары и аксессуары.
7. Добавить словарь брендов и опечаток: `беко -> beko`, `бе4о -> beko`, `гри -> gree`, `хомлайн -> homeline`.
8. Перенести реальные диалоги из Telegram-архивов в тестовые сценарии.
